# Phase 6.1 — Horizontal Cleanup — Design Spec

## 1. TL;DR

Phase 6.1 banks the **8 carry-forward items** the Phase 6 retro triaged to the N.1 cleanup
convention — no feature or migration work, no production endpoint behavior change. Two buckets:

- **Code (2):**
  - **RC-60** — harmonize service error handling: add the ERROR-dispatch permit to the 5
    `SecurityConfig`s that lack it (only inventory has it today) so an unhandled controller
    exception surfaces its **real** status instead of being masked as a spurious 401, and codify
    it as a new-service reviewer check.
  - **RC-61** — extract the byte-duplicated JWT/cookie test helper into a `jwt-auth-common`
    test-fixture so it isn't copy-pasted into a 7th service.
- **Docs (6):** codify lessons **RC-57, RC-58, RC-59, RC-62, RC-63, RC-65** into `docs/process/`.

The phase's value is **derisking Phase 6.5**: the heavier write/restructure work lands on a
codebase whose error contract is uniform, whose test-auth boilerplate is shared, and whose
reviewer checklist has the three Phase-6 bug-classes (RC-57/58/59) baked in.

## 2. Done state

All 6 Spring Boot services return honest error statuses (no 401-masking of 500s), with the
standard documented so the next cloned service inherits it. The JWT test helper lives once in
`jwt-auth-common`'s test fixtures and is consumed identically by catalog/organization/location/
inventory. Six process lessons are codified in their target docs. The full `services/` build +
existing TestContainers integration tests + the RC-16 e2e remain green; no endpoint response
changes shape.

## 3. Forced design decisions

### FD#1 — RC-60 standard: ERROR-dispatch permit baseline (NOT a shared error-body advice)

The 401-mask happens because Spring Security's filter chain is registered for **all** dispatch
types. An unhandled controller exception triggers an internal container forward to `/error` (a
second dispatch of type `ERROR`); the chain re-runs, the `SecurityContext` is already cleared,
`/error` isn't permitted, so `anyRequest().authenticated()` fires and `HttpStatusEntryPoint(401)`
returns 401 — masking the true 500.

**Decision:** standardize on `.dispatcherTypeMatchers(DispatcherType.ERROR).permitAll()` as the
first matcher in every service's `authorizeHttpRequests` block. This is the idiomatic Spring
Security 6 fix and the **only** option that covers exceptions thrown *outside* a controller
(filters, async) — a `@ControllerAdvice` cannot. The existing `GlobalExceptionHandler`s in
catalog/identity/document are **kept unchanged** as the *shaping* layer for known 4xx; a
more-specific `@ExceptionHandler` always wins over the now-permitted `/error` fallback, so there
is no conflict and no body change.

**Rejected — a shared `@RestControllerAdvice` in `jwt-auth-common` giving uniform error bodies**
(user-decided, YAGNI): it solves a problem nobody has hit (differing bodies, not wrong statuses),
it would **rewrite inventory's just-shipped RC-16 500 body** (Phase 6 deliberately preserved
Grails' default-500-no-custom-body), and it makes every service depend on a shared error contract.
The door stays open if uniform bodies ever become a requirement; it composes with the permit then.

### FD#2 — RC-61: parameterless shared fixture via `java-test-fixtures`

Add Gradle's built-in `java-test-fixtures` plugin to `services/jwt-auth-common`. A new
`JwtTestFixtures` class exposes the three shared pieces: `TEST_SECRET` (constant), `validToken()`
(subject `test-user`, roles `[ROLE_BROWSER]`, 1h expiry, HMAC over `TEST_SECRET`), and
`authCookie()` (a cookie named via `JwtService.COOKIE_NAME` — reused, not re-literal'd). Consumed
via `testImplementation(testFixtures(project(':jwt-auth-common')))`.

**Decision (user-confirmed): the fixture is parameterless and location is normalized to it.**
Verification (A4b) proved location's drift — `subject("test-user-id")` + an extra
`.claim("loc","loc-depot-a")` — is **non-functional**: neither location-service nor `JwtService`
reads the `loc` claim or the subject value, and `loc-depot-a` in the test is a URL path id, not the
claim. The four consumers (catalog, organization, location, inventory) therefore all call the
identical fixture; location loses its unused drift. This is the cleanest end state and matches the
checklist's own RC-24 "5th-copy rule" (the customization that would have forced parameterization is
cosmetic, so it's removed rather than parameterized).

identity (issues its own tokens) and document (no signed-token helper) are untouched.

### FD#3 — RC-63 home: a new `docs/process/sdd-controller-practices.md`

Five of the six codifications append to an existing doc. **RC-63** (the SDD controller de-risks
infra/data-coupled tasks before dispatching an implementer) has no existing home — it is neither a
reviewer check, a plan-ordering rule, nor a dev-env recipe. It gets a short dedicated doc, added to
the `docs/process/README.md` Files index, keeping each process file single-purpose.

### FD#4 — Doc codifications relocate retro lessons into permanent process docs

The 6 doc items move lessons from the (phase-scoped) retro into the (cross-phase) process docs that
plan-writers and reviewers consult. They follow the established `## <title> (Phase X RC-Y)` +
**Rationale** + **Verification** section convention. Content is the retro's already-written lesson,
tightened; no new claims are invented.

## 7. Risks

- **Adding the ERROR-permit changes unhandled-exception responses from 401 → 500** in
  catalog/identity/organization/document/location. *Mitigation:* this is the intended honest
  behavior; **A2 verified** that no existing test or e2e asserts a 401 for an
  unhandled-exception path (every 401 assertion is a no-cookie / bad-jwt / bad-credentials case).
- **`testFixtures` dependency wiring** (jjwt on `testFixtures*` configs; `jakarta.servlet` for the
  `Cookie` type). *Mitigation:* consumers already carry jjwt (impl+runtimeOnly) and servlet
  (`spring-boot-starter-test`) on their test classpath; the full `services/ test` run is the proof.
- **Normalizing location's test token.** *Mitigation:* **A4b verified** the dropped subject/`loc`
  are unread; location's tests authenticate identically on the common token.
- **Small-LOC-change optics** (a cleanup phase removes/standardizes, doesn't add features). *Same
  framing as prior N.1 phases:* the value is uniform error contracts + dedup + a hardened reviewer
  checklist before Phase 6.5's heavier work.
