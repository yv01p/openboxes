**Goal:** Reconcile the shipped flat catalog-service write contract with the real React ProductSupplier composite form/list — keep the flat contract, move the React seam to it — while completing the remaining Phase 5.5 catalog migration (the supplier write-cluster T3–T5, the list-query backend, the other deferred entities T6–T11, Category writes T12, partial RC-13 cleanup T13), and ship a cluster-end cutover that re-points the form/list to catalog-service. Tag `phase-5.5-catalog-deferred`.

**Architecture:** Extends the existing catalog-service Spring Boot module (no new Gradle subproject). The flat FK-only DTO decision (parent FD#2) and the JPA-audit infra built in T2 (FD#8 Option-A: `JwtAuditorAware` + `@EnableJpaAuditing`) are kept and reused. The reconciliation: (1) immediate forward corrections — revert T2's nginx repoint so the live Grails form works again, add a catalog-service `@RestControllerAdvice` that turns write-path failures into honest 4xx instead of a `/error`-forwarded spurious 401, and codify the synthetic-payload lessons-learned; (2) build the supplier write-cluster (T3 ProductSupplierPreference, T4 ProductPackage, T5 ProductPrice) as **backend + integration tests only** — no per-task nginx repoint, no per-task React change, no per-task through-nginx e2e — each adding the read GET(s) the cutover will assemble from; (3) a list-query backend sub-task giving the list page filtering + pagination (`{data,totalCount}`) + sorting; (4) the other deferred entities T6–T11 + Category writes T12 + partial RC-13 cleanup T13 unchanged from the parent design; (5) one cluster-end cutover that rewrites the React form load to client-side join over flat GETs, rewrites the save to flat keys, points the list page at catalog, repoints nginx for the whole cluster (excluding `productSupplierAttributes`, which stays on Grails), re-enables the parked e2e, and ships Option-C tests (Playwright UI-driving + API-shape). React stays Grails-hosted; SPA decoupling stays Phase 12 (parent A19).

**Tech stack:** Spring Boot 3.3.5 + Java 21 + Hibernate 6 / JPA 3.0 (jakarta.persistence) + Spring Data JPA auditing (`AuditingEntityListener` / `@EnableJpaAuditing` / `AuditorAware<String>`) + Liquibase 4.20+ (shadow changelogs: `tableExists` precondition + empty body) + Spring Security 6 (HMAC HS256 JWT cookie auth via `services/jwt-auth-common`) + springdoc-openapi 2.5.0 + jjwt 0.12.5 + MariaDB JDBC 3.4.1 + TestContainers 1.21.3 (MariaDB 10) + JUnit 5 + MockMvc; Playwright 1.40+ (chromium; `e2e/` `npm test`); Gradle multi-module at `services/` (`./gradlew :catalog-service:test` from `services/`); Docker Compose v2; nginx 1.27 reverse proxy at `docker/nginx/conf.d/app.conf` (Rule 3 exact-match-before-prefix per `docs/process/plan-ordering-rules.md`); GitHub Actions CI (`backend-tests.yml` Grails unit+integration; `e2e-tests.yml` lint + Playwright full-stack); Grails 3.3.x legacy monolith at `grails-app/` + React (webpack→`.gsp`) at `src/js/`.

  ```java
  package org.openboxes.catalog.web;

  import org.springframework.dao.DataIntegrityViolationException;
  import org.springframework.http.ResponseEntity;
  import org.springframework.http.converter.HttpMessageNotReadableException;
  import org.springframework.web.bind.MethodArgumentNotValidException;
  import org.springframework.web.bind.annotation.ExceptionHandler;
  import org.springframework.web.bind.annotation.RestControllerAdvice;

  import java.util.Map;

  // Maps catalog write-path failures to honest 4xx IN-DISPATCHER, so the request is never
  // forwarded to /error (which would re-enter the security chain and return a spurious 401 via
  // HttpStatusEntryPoint(UNAUTHORIZED) — see write-contract-reconciliation design §6).
  // Handled set is extended per task as write paths land (T3: DuplicatePreferenceException).
  @RestControllerAdvice
  public class GlobalExceptionHandler {

      // Uniqueness/constraint conflict at the DB layer (e.g. ProductPackage's unique index).
      @ExceptionHandler(DataIntegrityViolationException.class)
      public ResponseEntity<Map<String, String>> conflict(DataIntegrityViolationException e) {
          return ResponseEntity.status(409).body(Map.of("error", "constraint violation"));
      }

      // Bad or unreadable request body.
      @ExceptionHandler({MethodArgumentNotValidException.class, HttpMessageNotReadableException.class})
      public ResponseEntity<Map<String, String>> badRequest(Exception e) {
          return ResponseEntity.status(400).body(Map.of("error", "bad request"));
      }
  }
  ```
