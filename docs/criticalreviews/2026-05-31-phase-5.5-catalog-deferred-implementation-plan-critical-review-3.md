## 2. Literal-wrongness findings

**Finding 1: T2 Step 10's seed.sql INSERT references `test-product-1-fixture` as a Phase-5 product ID — that ID does not exist in the actual seed.sql, so the INSERT fails on the JPA-generated FK constraint at integration-test load time.**

- Description: T2 Step 10's seed.sql example (plan lines 397-399):
  ```sql
  INSERT INTO product_supplier (id, code, name, product_id, supplier_id, active, date_created, last_updated)
  VALUES ('test-ps-1-fixture', 'TEST-PS-1', 'Test Supplier 1', 'test-product-1-fixture', 'test-org-1-fixture', true, NOW(), NOW());
  ```
  The accompanying parenthetical (plan line 400) asserts: "`test-product-1-fixture` must exist from Phase 5 seed". This is empirically false. The actual Phase-5 `services/catalog-service/src/test/resources/seed.sql` (lines 37-40) inserts products with IDs `p-bandage`, `p-syringe`, `p-iv-drip` — there is no `test-product-1-fixture` row, and the naming convention used throughout the file is `p-<kebab-name>` / `tag-<name>` / `cat-<name>` / `pt-<name>` / `uom-<name>`.

  Because T2's `ProductSupplier.java` declares `@ManyToOne(fetch = FetchType.LAZY, optional = false) @JoinColumn(name = "product_id", columnDefinition = "CHAR(38)") private Product product;` (plan lines 242-244), Hibernate generates a real DB-level FK constraint on `product_supplier.product_id → product.id` when `ddl-auto=create` builds the schema in tests (verified at `CatalogServiceIntegrationTest.java:39` — `r.add("spring.jpa.hibernate.ddl-auto", () -> "create");`). The seed.sql load runs after schema creation (`spring.jpa.defer-datasource-initialization=true` at `CatalogServiceIntegrationTest.java:40`). When seed.sql tries to insert `product_id='test-product-1-fixture'`, MariaDB raises a FK constraint violation; Spring fails the application-context bootstrap; every `@SpringBootTest` method aborts.

  T2's Step 13 (`./gradlew :catalog-service:test`) therefore fails. T2 cannot pass its own gate. Since T3-T11 inherit T2's template and seed-fixture pattern under the "deltas only" framing (plan line 152), they would likely echo the same broken fixture-ID convention.

  Note: the plan-line-400 carve-out for `'test-org-1-fixture'` ("the FK is unenforced at JPA level per FD#2, so any CHAR(38) string works") is correct for the cross-service `supplier_id` column (declared as raw `@Column` String, no JPA FK — plan lines 247-248). The carve-out does NOT extend to `product_id`, which IS a JPA `@ManyToOne` and DOES get a FK constraint.

- Evidence:
  - Plan lines 396-400 (T2 Step 10 seed.sql example + the "must exist from Phase 5 seed" claim)
  - Plan lines 242-244 (T2 Step 2 declares `@ManyToOne(optional=false) Product product` with `@JoinColumn` → Hibernate generates FK)
  - `services/catalog-service/src/test/resources/seed.sql:37-40` — actual products are `p-bandage`, `p-syringe`, `p-iv-drip`; no `test-product-*` row
  - `services/catalog-service/src/test/java/org/openboxes/catalog/CatalogServiceIntegrationTest.java:39` (`ddl-auto=create` generates FK constraints from JPA mappings)
  - `services/catalog-service/src/test/java/org/openboxes/catalog/CatalogServiceIntegrationTest.java:40-41` (`defer-datasource-initialization=true` + `data-locations=classpath:seed.sql` — seed runs after schema creation, against the FK-constrained table)

- Proposed fix: replace the seed.sql example's `'test-product-1-fixture'` literal with one of the existing Phase-5 product IDs, and tighten the accompanying claim to reference the real ID.
