## 2. Literal-wrongness findings

### Finding 1 — T13's `ApiSpec.groovy` cleanup names a non-existent helper and underspecifies the inlining; following the spec literally either no-ops the cleanup or breaks every integration test

**Description.** The round-1 UDD edit added cleanup of `ApiSpec.groovy:19,98,244` to the RC-13 section, FD#4 enumeration (bullet 4), and the T13 task row. All three locations describe the work as "remove the `CategoryApiWrapper` import + `@Autowired` field + `createTestCategory()` helper (inline `new Category(...)` via GORM at any sibling caller if the helper is reused)." Two factual problems make this prescription unsafe to execute as written:

1. **No `createTestCategory()` exists in the codebase.** The actual helper at `src/integration-test/groovy/org/pih/warehouse/api/spec/base/ApiSpec.groovy:243-248` is named `createRootCategory()`. A plan-writer or implementer who follows the spec literally and runs `grep createTestCategory` finds nothing to remove and either silently skips the change (leaving `categoryApiWrapper.createOK(...)` referring to a deleted wrapper → compile failure) or has to abandon the spec and reverse-engineer the right name.
2. **The "if the helper is reused" hedge is wrong — the helper IS reused, and removing it without an inline replacement breaks every `ApiSpec` subclass test.** `ApiSpec.groovy:164` calls `rootCategory = createRootCategory()` inside `setup()` (which runs before every test in every subclass). The resulting `rootCategory` field at line 86 is consumed by `createMainProduct()` at line 239 (`.category(rootCategory)`), and `createMainProduct()` is itself called from `setup()` at line 165 (`product = createMainProduct()`). So deleting the helper but leaving line 164 → compile failure. Deleting the helper AND line 164 → `rootCategory` stays null → `createMainProduct()` builds a Product with a null category → likely a `ProductTestBuilder` NPE or a downstream Product-validation failure in setup → every `ApiSpec` subclass test fails. The cleanup as written is not the "smallest fix that resolves the finding"; it's a fix that introduces a regression.

**Evidence.**
- `src/integration-test/groovy/org/pih/warehouse/api/spec/base/ApiSpec.groovy:86` — `@Shared Category rootCategory`.
- `src/integration-test/groovy/org/pih/warehouse/api/spec/base/ApiSpec.groovy:164` — `rootCategory = createRootCategory()` inside `setup()`.
- `src/integration-test/groovy/org/pih/warehouse/api/spec/base/ApiSpec.groovy:165` — `product = createMainProduct()` in the same setup.
- `src/integration-test/groovy/org/pih/warehouse/api/spec/base/ApiSpec.groovy:236-241` — `createMainProduct()` body, `.category(rootCategory)` at `:239`.
- `src/integration-test/groovy/org/pih/warehouse/api/spec/base/ApiSpec.groovy:243-248` — `private Category createRootCategory()` body invokes `categoryApiWrapper.createOK(new CategoryTestBuilder().name("Test Root Category").rootCategory().build())`.
- `grep -rn "createTestCategory" src/integration-test` (and across `src/`) returns empty — the name does not exist.

**Proposed fix.** Three coordinated edits to the spec (no scope expansion beyond fixing what the round-1 UDD got wrong):

1. In the RC-13 partial-cleanup section (the bullet added in round 1), change `createTestCategory()` → `createRootCategory()` and replace the parenthetical with: *"keep the helper signature at `ApiSpec.groovy:243` and the `rootCategory` field at `ApiSpec.groovy:86`; swap the helper body to GORM-direct `Category` construction (e.g., construct + save a root `Category` directly via the domain class rather than the HTTP wrapper). Line 164's `rootCategory = createRootCategory()` invocation stays. Then delete the import at line 19 and the `@Autowired CategoryApiWrapper categoryApiWrapper` field at line 98."*
2. Same fix in the FD#4 bullet 4.
3. Same fix in the T13 task-row description.

The T13 file counts in the rightmost column (`MODIFY: 4 … ApiSpec.groovy`) remain correct — `ApiSpec.groovy` is still modified (now: import removed, wrapper field removed, helper body rewritten). The DELETE count (4: CategoryApiControllerTests + CategoryApiCRUDSpec + CategoryApi + CategoryApiWrapper) also remains correct.
