### 2.1 T4 Step 5 — T7-M1 logging verification will silently fail; document-service `application.yml` logging config targets the now-empty local package after migration

**Description.** `services/document-service/src/main/resources/application.yml` at lines 32-34 declares:

```yaml
logging:
  level:
    org.openboxes.document.security: DEBUG
```

(With comment "Surface JwtCookieAuthFilter's rejection log (T7-M1)…")

This DEBUG-level override was added during document-service's original deployment specifically because the canonical `logger.debug("JWT cookie rejected: …")` line is below Spring Boot's default INFO threshold. After T4 deletes `services/document-service/src/main/java/org/openboxes/document/security/JwtCookieAuthFilter.java`, the bean comes from `org.openboxes.auth.common.JwtCookieAuthFilter` (different package). The DEBUG-level config still targets `org.openboxes.document.security` — a package that no longer contains the filter — so the rejection logger reverts to default INFO level and the DEBUG line is no longer emitted.

T4 Step 5's verification:

```bash
sudo docker logs openboxes-document-service 2>&1 | grep "JWT cookie rejected"
```

returns zero matches because the log line isn't emitted, even though the catch block fires correctly. The "Expected: log line `JWT cookie rejected: <ExceptionClassName>`" framing then misleads the implementer into thinking T7-M1 logging was lost — when it was actually intact, just suppressed by mismatched log-level config.

This is the "spec's stated outcome" failure: T4's premise is "T7-M1 logging discipline preserved (moved into the starter's filter)". Without the config update, the discipline is preserved in code but unobservable in the running document-service, defeating the verification path the plan itself prescribes.

**Evidence.** `services/document-service/src/main/resources/application.yml:32-34` (logging.level config); plan T4 Files: section omits `application.yml`; plan T4 Step 5 grep command relies on DEBUG line emission.

**Proposed fix.** Add to T4:
- **Modify** `services/document-service/src/main/resources/application.yml`: change `org.openboxes.document.security: DEBUG` → `org.openboxes.auth.common: DEBUG` (or duplicate the entry to cover both during migration, then remove the document-side entry once the deletion confirms no other class in `org.openboxes.document.security` needs DEBUG).
- Insert this edit as a new step BEFORE Step 5 (verification), e.g., new "Step 4.5: Update document-service logging.level config to point at starter's package".
- Update T4's `Files:` block: `Modify: 3` (was 2) — add `application.yml`.
- Update T4 Step 7 commit message + `git add` to include the application.yml path.

Other services (catalog/location/organization/identity) have NO equivalent DEBUG override and gain T7-M1 logging at default INFO (silent) — that's not a regression there since they previously had no filter-rejection logging at all (canonical filter pre-migration had no try/catch).
