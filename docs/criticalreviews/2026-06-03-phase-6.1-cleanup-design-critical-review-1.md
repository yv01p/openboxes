That is wrong: the shared `JwtCookieAuthFilter` (`jwt-auth-common`, used by every service) reads `claims.get("sub")`, `claims.get("loc")`, and `claims.get("roles")` (`JwtCookieAuthFilter.java:34-41`) and sets them as `userId`/`locationId`/`roleIds` request attributes + the auth principal (`sub`). Confirmed by the peer baseline: catalog/org/inventory already run on the loc-less common token (no `getAttribute("locationId")` callers). **Recommended fix:** reword FD#2 / A4b to "the shared filter derives `locationId`/`userId`/`roleIds` from the token, but location-service consumes none of them (only the `authenticated()` gate matters), and the 3 peer services already authenticate on loc-less tokens — so dropping `loc`/changing the subject is immaterial." Conclusion (safe to normalize) is unchanged.
