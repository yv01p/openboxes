## 2. Literal-wrongness findings

**Finding 1: T2 Step 2 (and T9) reference Grails-side enums `RatingTypeCode` / `ProductAssociationTypeCode` that don't exist in catalog-service — `javac` will fail.**

- Description: T2 Step 2's `ProductSupplier.java` code (plan line 263) declares:
  ```java
  @Enumerated(EnumType.STRING)
  @Column(name = "rating_type_code")
  private RatingTypeCode ratingTypeCode;
  ```
  `RatingTypeCode` is a Grails-side enum at `src/main/groovy/org/pih/warehouse/core/RatingTypeCode.groovy`. It does not exist anywhere under `services/catalog-service/src` (`grep -rn "RatingTypeCode" services/catalog-service/src` returns empty), and T2's Files-to-Create list (plan line 193-205) lists no enum. The plan's T2 Step 2 imports block (plan lines 216-223) imports `jakarta.persistence.*` + Spring Data JPA audit annotations + `java.time.Instant` + `java.math.BigDecimal`, but no `RatingTypeCode`. T2 Step 13 (`./gradlew :catalog-service:test`) compiles `ProductSupplier.java`; `javac` fails with `cannot find symbol: class RatingTypeCode`. T2 cannot pass its own gate.

  The same issue exists in T9 (ProductAssociation): plan line 517 says "`code` is `ProductAssociationTypeCode` enum (catalog-internal)". `ProductAssociationTypeCode` is at `src/main/groovy/org/pih/warehouse/product/ProductAssociationTypeCode.groovy` — Grails-side only; no catalog-service Java enum, no T9 Create entry, no T9 import in the implied entity body.

  **The plan's stated approach diverges from the established Phase-5 convention.** The Phase-5 catalog-service entities all handle Grails-side enum-typed fields as **plain `String` columns** with a documentation comment, NOT as Java enums with `@Enumerated`. Verified at:
  - `services/catalog-service/src/main/java/org/openboxes/catalog/entity/Synonym.java:18` — `private String synonymTypeCode;  // SynonymTypeCode enum stored as String`
  - `services/catalog-service/src/main/java/org/openboxes/catalog/entity/UnitOfMeasureClass.java:17` — `private String type;  // UnitOfMeasureType enum stored as String`
  - `services/catalog-service/src/main/java/org/openboxes/catalog/entity/ProductType.java:15` — `private String productTypeCode;  // ProductTypeCode enum stored as String`

  Per the plan's File Structure section (line 9): "Extends the existing catalog-service Spring Boot module" and the per-entity template "(per Phase-5 pattern)" framing throughout. The Phase-5 pattern is "store enum-typed Grails fields as String columns." The plan picks a different pattern (Java enum + `@Enumerated(EnumType.STRING)`) for the new entities — but doesn't ship the enum classes that the pattern requires.

- Evidence:
  - Plan lines 262-264 (T2 `ProductSupplier.java` code block, `@Enumerated`/`RatingTypeCode` declaration)
  - Plan lines 216-223 (T2 Step 2 imports — no `RatingTypeCode` import)
  - Plan lines 193-205 (T2 Files-to-Create list — no enum file)
  - Plan line 517 (T9 `ProductAssociationTypeCode` reference, same issue)
  - `grep -rn "RatingTypeCode" services/catalog-service/src` returns empty (no such class in catalog-service)
  - `src/main/groovy/org/pih/warehouse/core/RatingTypeCode.groovy` (Grails-side definition only)
  - `src/main/groovy/org/pih/warehouse/product/ProductAssociationTypeCode.groovy` (Grails-side definition only)
  - `services/catalog-service/src/main/java/org/openboxes/catalog/entity/Synonym.java:18`, `UnitOfMeasureClass.java:17`, `ProductType.java:15` (established Phase-5 convention: String + comment)

- Proposed fix (pick one — both resolve `javac` failure; (b) also brings T2/T9 into alignment with the Phase-5 convention):
  - **(a) Add Java enum files to T2's and T9's Create lists.** New files: `services/catalog-service/src/main/java/org/openboxes/catalog/entity/RatingTypeCode.java` (with `NOT_RATED` and the other Grails enum values) for T2; `services/catalog-service/src/main/java/org/openboxes/catalog/entity/ProductAssociationTypeCode.java` (with `SUBSTITUTE` and the other Grails enum values) for T9. Keeps the plan's `@Enumerated(EnumType.STRING)` typing. **Downsides:** introduces a new convention that diverges from Phase 5; requires keeping the catalog-service enum in sync with the Grails one (drift risk).
  - **(b) Conform to the Phase-5 String-with-comment convention.** Replace T2's `RatingTypeCode ratingTypeCode` field with `private String ratingTypeCode;  // RatingTypeCode enum stored as String` (matching `Synonym.java:18`). Replace T9's `ProductAssociationTypeCode code` similarly with `private String code;  // ProductAssociationTypeCode enum stored as String`. Drop the `@Enumerated` annotation in both places. DB column type is already VARCHAR-holding-the-enum-name in both Hibernate enum-as-string serialization AND Phase-5's plain-string serialization, so DB compatibility is preserved. No new files; no drift risk; matches established convention.

  Option (b) is the smallest fix that resolves the finding AND aligns with the established codebase pattern.
