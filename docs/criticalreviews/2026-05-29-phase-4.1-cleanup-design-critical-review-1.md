## 3. Forced decisions

### Decision 1: nginx proxy_params include — migration scope (6 blocks vs 8 blocks)

**The choice:** how many of the existing `app.conf` server blocks migrate from inline `proxy_set_header Host $host; proxy_set_header X-Forwarded-For $remote_addr; proxy_set_header Cookie $http_cookie;` triplet to `include /etc/nginx/conf.d/proxy_params;`.

**Why it's forced:** The spec's Architecture §3 says "6 service blocks in `app.conf` migrate" and Done state §6 says "6 blocks via include" — pinning 6. However, fresh grep of `docker/nginx/conf.d/app.conf` shows **8 blocks** with the byte-identical triplet:

| # | Block | Lines | Routes to |
|---|---|---|---|
| 1 | `location /api/identity` | 11-16 | identity-service:8082 |
| 2 | `location /api/documents` | 18-23 | document-service:8081 |
| 3 | `location = /api/location` | 25-30 | location-service:8083 |
| 4 | `location /api/location/` | 32-37 | location-service:8083 |
| 5 | `location = /api/organization` | 40-45 | organization-service:8084 |
| 6 | `location /api/organization/` | 47-52 | organization-service:8084 |
| 7 | `location /api/` (Grails API catch-all) | 54-59 | app:8080/openboxes/api/ |
| 8 | `location /openboxes/` | 61-66 | app:8080/openboxes/ |

Blocks 1-6 are the "service blocks" (Spring Boot microservices). Blocks 7-8 are Grails catch-alls but use the IDENTICAL triplet. The spec's "6" silently picks blocks 1-6 only — leaving 2 of 8 instances of the duplicated triplet unmigrated.

The Phase 4 retro RC-11 wording (`nginx proxy_set_header blocks duplicated across N service entries`) is ambiguous: "service entries" could mean Spring Boot services only (favoring 6) or any block-with-the-triplet (favoring 8).

The spec made the pick silently. Per the design-review discipline, this is a forced decision the user should confirm before plan-writing.

**The options:**

- **(a) 6 blocks — service-only migration (current spec assumption).** Blocks 1-6 migrate; the 2 Grails-routed catch-alls (`/api/` and `/openboxes/`) keep their inline headers. **Rationale**: keeps the migration cleanly within "Spring Boot service routing" scope; doesn't perturb Grails-facing nginx behavior. **Cost**: RC-11 partially addressed — 2/8 duplicates remain. Future Phase 5+ adding new Spring Boot services + new Grails-side routing changes may re-encounter the same pattern. Done state §6 smoke = 6 tests.

- **(b) 8 blocks — full triplet-coverage migration.** All blocks with the identical triplet migrate to `include`. **Rationale**: actually eliminates the duplication completely; RC-11 fully addressed; future phases adding service OR Grails-side routes can use the same include directly. **Cost**: touches the `/api/` Grails catch-all + `/openboxes/` block, which are stable from Phase 0; risk of perturbation though tested via nginx -t + reload smoke. Done state §6 smoke = 8 tests (need to add 2 smokes — one for `/api/` proxied-to-Grails endpoint, one for `/openboxes/` GSP route).

- **(c) 6 now, document the 2 catch-alls as "deferred to Phase 5+ when Grails routing changes again."** Migrate blocks 1-6; add an inline comment in `app.conf` next to `/api/` and `/openboxes/` blocks: `// NOTE: shares the proxy_params triplet but not yet migrated; consider during next nginx structural change`. **Rationale**: same risk profile as (a); leaves a grep-discoverable breadcrumb for future phases. **Cost**: small comment addition; otherwise same as (a).
