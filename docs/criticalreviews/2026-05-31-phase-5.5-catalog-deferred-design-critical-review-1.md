## 2. Literal-wrongness findings

### Finding 1 — T13 cleanup deletes URL mappings still consumed by active integration tests; CI will fail done-state #3

**Description.** T13 scope (spec lines 96-107, T13 row in the task table at line 173, done-state #9 at line 205) plans to remove `UrlMappings.groovy:45-52` (the `/api/categories` + `/api/categories/$id` mappings to `categoryApi`) and update the Grails-unit-test files at `src/test/groovy/.../UrlMappingsSpec.groovy` + `src/test/groovy/.../CategoryApiControllerTests.groovy`. T13 does **not** include the active integration-test suite that also calls `/api/categories`. Once the URL mappings are gone, 4 currently-passing `CategoryApiCRUDSpec` tests (and the 1 currently-passing delete-fail-when-missing test) will start returning 404 from the embedded Grails server and the `backend-tests` CI workflow — which is a required check on PRs and on push to `main` — will fail.

**Evidence.**
- `src/integration-test/groovy/org/pih/warehouse/api/spec/product/CategoryApiCRUDSpec.groovy:36-82` — five test methods exercising `categoryApiWrapper.api.{get, list, create, delete}` against the running Grails server.
- `src/integration-test/groovy/org/pih/warehouse/api/client/product/CategoryApi.groovy:17-52` — `Method.{GET, POST, PUT, DELETE}` against `/categories` and `/categories/{categoryId}`.
- `src/integration-test/groovy/org/pih/warehouse/api/spec/base/ApiSpec.groovy:196` — `RestAssured.basePath = "/openboxes/api"`. Final URI = `/openboxes/api/categories`, which Grails resolves via `UrlMappings.groovy:45`.
- `src/integration-test/groovy/org/pih/warehouse/api/spec/base/ApiSpec.groovy:19,98,244` — `import …CategoryApiWrapper`, `@Autowired CategoryApiWrapper categoryApiWrapper`, and `categoryApiWrapper.createOK(new CategoryTestBuilder()…)` helper used by sibling specs. Removing the wrapper requires touching these too.
- `.github/workflows/backend-tests.yml:37` runs `./gradlew jacocoTestReport`, and `build.gradle:891` sets `jacocoTestReport.dependsOn test, integrationTest` (and `:894` `executionData test, integrationTest`) — so the integration suite runs in CI.
- `.github/workflows/test-pull-request.yml:15-16` (`run-backend-tests: uses: ./.github/workflows/backend-tests.yml`) and `.github/workflows/on-change.yml:13-14` — `backend-tests` is wired into the PR pipeline and the push-to-main pipeline.
- Spec done-state #3 (line 199): "CI green on the final push (E2E Tests workflow: both `lint` + `e2e` jobs)." The phrasing names only the E2E workflow but does not waive the `backend-tests` workflow, which is still required on the PR; an integration-test red status blocks the merge regardless.

**Proposed fix.** Extend T13's scope (and the FD#4 enumeration at lines 96-107) to also handle the integration-test suite. Two acceptable shapes:

1. **Delete-and-collapse (recommended given the API moves to catalog-service):** in the same T13 commit,
    - `git rm src/integration-test/groovy/org/pih/warehouse/api/spec/product/CategoryApiCRUDSpec.groovy`
    - `git rm src/integration-test/groovy/org/pih/warehouse/api/client/product/CategoryApi.groovy`
    - `git rm src/integration-test/groovy/org/pih/warehouse/api/client/product/CategoryApiWrapper.groovy`
    - In `src/integration-test/groovy/org/pih/warehouse/api/spec/base/ApiSpec.groovy`: remove the `import …CategoryApiWrapper` (line 19), the `@Autowired CategoryApiWrapper categoryApiWrapper` field (line 98), and the `createTestCategory()` helper (line 244) — or inline whatever sibling specs use it for via the GORM domain directly (the helper currently does `categoryApiWrapper.createOK(new CategoryTestBuilder()…)`, so any caller can be redirected to construct a `Category` via GORM in `setupData()` if needed).
    - Coverage for the new POST/PUT/DELETE on `/api/category` lives in catalog-service's own integration-test module (added by T12 per its task description).
2. **Defer-the-mapping-removal:** keep `UrlMappings.groovy:45-52` and the `SecurityInterceptor.groovy:23 'categoryApi'` entry in place, and explicitly narrow T13/RC-13 partial scope to only the dead Grails-unit-test cleanups (or push the whole T13 to Phase 6). The cost is RC-13 not getting any progress at this phase, but Phase 6 already has to remove `CategoryApiController.groovy` itself (because of `runtime.groovy:757`), so removing the URL mappings concurrently with the controller is the natural moment.

The Recommended shape is option 1: the integration tests are conceptually exercising the Category REST API, which moves to catalog-service — keeping a Grails-side RestAssured suite for an endpoint that no longer lives there is the wrong steady state. Confirm that the new catalog-service integration tests added in T12 (or T11 if Category writes are tested under the existing `CatalogServiceIntegrationTest`) cover create/get/list/delete equivalents before deleting the Grails copies. Also add a verification step to done-state #9 (or new #9b): `grep -rln "CategoryApiWrapper\|CategoryApi\b" src/integration-test` returns empty.
